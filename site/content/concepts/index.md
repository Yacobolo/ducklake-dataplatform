# Concepts

Duck is easiest to understand when you separate five concerns:

- who is allowed to do something
- what object or product they are trying to use
- how the output is built and refreshed
- how the output is described for consumers
- where execution actually happens

## Mental Model

Duck is not only a secure SQL endpoint. It is also:

- a product catalog for reusable data contracts
- an orchestration graph for asset production and freshness
- a transformation framework for models, macros, tests, and notebook promotion
- a semantic layer for metrics and relationships
- an operations surface for auth, storage, compute, and integrations
